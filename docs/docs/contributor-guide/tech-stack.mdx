# Technology Stack

What Peach 1UP is built on and why.

## At a glance

| Layer | Choice |
|---|---|
| Platform | Windows 10/11 only |
| Backend | Python 3.14+, FastAPI, Pydantic, SQLModel |
| Database | SQLite, `create_all()` on startup, no Alembic |
| Frontend | TypeScript, React, Vite, TanStack Query, Tailwind v3, Radix primitives |
| Type bridge | FastAPI OpenAPI spec to `openapi-typescript` to `shared/types.ts` |
| Isolation | Windows Job Objects, AppContainer layered on top where supported |
| Packaging | PyInstaller, NSIS, WinSW, pystray |
| Docs | Docusaurus, served at `/docs` |
| Tooling | uv, Ruff, pytest, ESLint, Prettier, Vitest |

## Platform

Windows-only, permanently. The app runs natively on Windows 10/11 and emulators run natively
on the host OS. Linux support was removed from scope in July 2026 and the Linux code paths
were deleted with it.

## Backend

Python 3.14 or later, pinned via `requires-python` and matched by CI. FastAPI provides async
performance, automatic OpenAPI generation, and Pydantic validation.

| Library | Use |
|---|---|
| `argon2-cffi` | PIN hashing |
| `pycdlib` | ISO parsing |
| `httpx` | Outbound metadata calls |
| `PyYAML` | `eras.yaml`, `constants.yaml` |
| `python-dotenv` | `.env` secrets |

Two components are extracted into standalone packages and consumed as regular PyPI
dependencies:

| Package | Covers |
|---|---|
| [`formatscout`](https://pypi.org/project/formatscout/) | Disk-image and directory format detection, hashing, verification |
| [`wincage`](https://pypi.org/project/wincage/) | Windows AppContainer and Job Object sandboxing, plus `sandbox_host.exe` |

Both install via `uv sync` like any other dependency. `wincage`'s wheel is Windows-only
(`win_amd64`) and ships a prebuilt `sandbox_host.exe` inside the installed package
directory, no MSYS2 or other native build step required.

## Database

SQLite via SQLModel, `create_all()` on startup. Read-heavy single-library usage makes SQLite
sufficient, and the SQLAlchemy abstraction keeps Postgres a config change rather than a
rewrite. The connection is opened and closed per call; there is no long-lived hot connection.

Migrations were dropped deliberately: Alembic's overhead is not justified while the database
can still be wiped freely. It comes back when real user data has to survive schema changes.

## API bridge

FastAPI emits the OpenAPI spec; `openapi-typescript` generates the typed client into
`shared/types.ts`. There is no hand-maintained type duplication between backend and
frontend, so a schema change in Python propagates to TypeScript automatically.

## Frontend

React for ecosystem size and developer availability, TypeScript throughout. Radix UI
primitives (dialog, tabs, toast, collapsible, slot) back a hand-rolled component library on
an RGB-triplet CSS variable color system with skin scaffolding.

Tailwind is pinned to v3. Do not upgrade until shadcn/ui supports v4.

## Emulators

| Emulator | Era | ROM or BIOS required |
|---|---|---|
| DOSBox-X | DOS | No |
| 86Box | Windows 95, 98, XP | Yes, 86Box ROM pack |
| DuckStation | PS1 | Yes, PS1 BIOS |
| PCSX2 | PS2 | Yes, PS2 BIOS |
| RPCS3 | PS3 | Yes, PS3 firmware |
| xemu | Xbox OG | Yes, Xbox BIOS |
| Xenia | Xbox 360 | No |
| Mesen | NES, SNES | No |
| Project64 | N64 | No |
| Flycast | Dreamcast | Yes, DC BIOS |

Every emulator installs on demand from its own upstream release rather than shipping in the
repository. Nine use GitHub releases. Project64 is the exception: the project publishes git
tags but no release assets, so the user downloads it manually. See the
[Emulator Reference](./emulators.mdx).

**DOSBox-X sound limitation.** DOS games that write sound config to their install directory
have no in-game sound when launched from a read-only ISO. Installing to a writable HDD image
fixes it. Direct ISO launch is intentionally read-only and cannot persist game config, so
this is expected behaviour, not a bug.

## Process isolation

Windows Job Objects, with AppContainer layered on top where the emulator supports it. Job
Objects provide kill-on-close plus a per-era CPU rate cap and per-process memory cap, and
**all three are enforced today**: no descriptor waives either cap.

Network blocking is emulator-native, applied on every launch. Full detail:
[Windows Sandboxing](./windows-sandboxing.mdx) and
[Security Architecture](./security.mdx).

## Media detection

Detection lives in the vendored `formatscout` package. The Peach-specific launch-target
resolvers (PS3, Xbox 360 XEX, Xbox optical images) stayed in-tree.

Tiers run in order and short-circuit on the first confident match:

| Tier | Method | Notes |
|---|---|---|
| 1 | Full-file SHA-1, falling back to MD5 then CRC32 | Compared against a bundled index built from No-Intro and Redump DATs. For `.chd`, raw bytes never match Redump, so the CHD v5 header's embedded `rawsha1` is read instead |
| 2 | Magic bytes | Covers GDI, CDI, BIN, ISO, CHD |
| 3 | Structural validation | ISO 9660 PVD for volume label, publisher, and system ID, with an `.xbe` root scan as fallback. CHD metadata tags: `CHGD` means Dreamcast, `CHTR`/`CHT2` means PS1 or PS2 split by logical size. BIN/CUE resolves the cue sheet to its bin sibling first |
| 4 | Directory heuristics | `I386`, `WIN98`, `XPSP`, `SYSTEM.CNF`, `AUTORUN.INF`, DOS tool names, `.WAD` files |
| 5 | Extension and size | Weak signals only |

PS1 versus PS2 is resolved consistently by `SYSTEM.CNF` `BOOT`/`BOOT2` in both the
raw-sector and extracted-file paths.

### Known limitations

- **Hash-index coverage is PS1 and Xbox only.** Every other era falls through to the
  lower-confidence tiers regardless of whether the file is corrupted.
- **Xbox OG ISOs without `DEFAULT.XBE` at the root** do not resolve structurally; the
  magic-byte check is the fallback. Standard rips include it, so this is rare.
- **`.bin`/`.cue` pairs with no matching `.cue` sibling** return low confidence. CD layout
  cannot be resolved without a cue sheet.
- **`requires_install` is approximate** and gated to DOS and Win3.1 only. It checks whether
  every executable at a directory root is on the blocklist.
- **CHD era resolution is size-based.** A CHD's embedded hash is a hash of its internal raw
  hunk stream, a different hash space that never intersects the Redump index. True
  resolution needs full hunk decompression, which is deferred.

## Uploads

Three per-domain routers built from one factory, each gated by its own permission flag:

| Prefix | Permission | Allowed kinds |
|---|---|---|
| `/api/v1/uploads/software-games` | `can_manage_game` | file, folder, set |
| `/api/v1/uploads/software-media` | `can_manage_media` | file |
| `/api/v1/uploads/software-apps` | `can_manage_app` | file, folder |

Init declares the manifest and creates the progress job before any bytes move, chunks stream
in, and complete always returns 202 and finalizes as a background task. There is no inline
path.

Limits: 25 GB per file, 64 MB per chunk, both overridable through settings. Session creation
is rate limited to 10 per minute across all domains; per-chunk uploads are not, because a
legitimate large upload is hundreds of requests. There is no total-folder-size cap.

Every uploaded filename is sanitised and resolved under the destination root before any
write. A folder upload cleans up its entire destination on any single-file failure, so no
partial folder ingest is possible.

## CI

| Workflow | Jobs |
|---|---|
| `test.yml` | Type generation, backend (Ruff plus `pytest --cov` on Windows), frontend (ESLint, Prettier, production build, `vitest --coverage`), and a packaging smoke test that builds with PyInstaller and asserts the frozen exe serves `/api/openapi.json` |
| `codeql.yml` | Static analysis |
| `release.yml` | Tag-triggered Windows release build. The tag must match the version in `constants.yaml` or the build fails. Signing is stubbed pending an OSS certificate |

Runs on every push and pull request to `main`.
