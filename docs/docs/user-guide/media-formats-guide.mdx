# Media Formats

A disc image is a byte-for-byte copy of physical media. The file extension tells you the
container format, not necessarily the platform, a `.bin` file might be a PS1 track, a
Dreamcast sector dump, or a raw floppy image.

## How disc images work

### Magic bytes / file signature

The first few bytes of a file that identify its format. Software reads these to confirm what a file actually is, regardless of extension. A `.bin` file might be a PS1 track dump, a Dreamcast sector image, or a raw floppy, magic bytes tell the truth.

[List of file signatures →](https://en.wikipedia.org/wiki/List_of_file_signatures)

### File header

Structured metadata at the start of a file describing its contents, version, and layout. Emulators read headers to configure themselves before loading any game data, the iNES header in a `.nes` file tells Mesen the mapper number and mirroring mode before a single byte of game code runs.

[FAT filesystem header reference →](https://wiki.osdev.org/FAT)

### Sector size

Disc media is divided into fixed-size sectors. CDs use 2048-byte sectors (data only) or 2352-byte sectors when raw error-correction data is included. GD-ROM (Dreamcast) always uses raw 2352-byte sectors; standard DVDs use 2048. The sector size determines how a disc image must be read and whether formats are interchangeable.

[CD-ROM sector structure →](https://en.wikipedia.org/wiki/CD-ROM#Sector_structure)

### Memory addresses (offsets)

A byte offset is the distance from the start of a file to a specific piece of data, measured in bytes. Detection logic reads specific offsets to find magic bytes or headers without loading the whole file. This is how Peach 1UP identifies disc images: it checks known offsets for platform-specific signatures rather than trusting the file extension.

## Format compatibility by emulator

| Emulator | Platform | Supported formats | Recommended | Notes |
| --- | --- | --- | --- | --- |
| DOSBox-X | DOS / Win 3.1 | `.iso, .img, .zip, .exe, .com, folder` | `.iso or folder` | No disc magic required. Loose executables, folders, and ZIP archives are all mountable. |
| 86Box | Win 95/98/XP | `.iso, .img, .vhd` | `Pre-installed .img or .vhd` | OS must be pre-installed in the image. Installer ISOs work but require manual setup. |
| DuckStation | PS1 | `.iso, .bin/.cue, .chd, .zip` | `.chd` | CHD reduces file size significantly with no quality loss. ZIP of a bin/cue or iso loads directly. |
| PCSX2 | PS2 | `.iso, .bin/.cue, .chd, .zip` | `.chd` | Full PS2 BIOS set required. ZIP-wrapped ISOs are supported. |
| Flycast | Dreamcast | `.gdi, .cdi, .chd, .zip` | `.chd` | GDI is the most accurate raw format. CHD compresses GDI cleanly. ZIP supported for CDI and single-track images. |
| Mesen | NES / SNES | `.nes, .sfc, .smc, .zip` | `.nes / .sfc` | No BIOS required for standard titles. ZIP archives load directly and are faster to scan in large collections. |
| Project64 | N64 | `.z64, .n64, .v64, .zip` | `.z64` | `.z64` is big-endian native; `.v64` is byteswapped, both work. ZIP archives are supported. |
| xemu | Xbox OG | `.iso (xiso format only)` | `xiso-format .iso` | Raw DVD rips (7–8 GB) are rejected. Must be converted with extract-xiso before use. |

## Converting and preparing disc images

### Xbox: converting a raw DVD rip to xiso

Raw DVD rips of Xbox games contain a video partition, a stub of video content that shipped on every
Xbox disc to prevent the drive from booting on a standard DVD player. xemu expects a clean XDVDFS
image with this partition stripped. Raw rips are typically 7–8 GB; after stripping they shrink to
2–4 GB.

Peach 1UP detects the difference automatically by checking for the `MICROSOFT*XBOX*MEDIA` magic
string at offset `0x10000`. A raw DVD rip instead shows standard ISO 9660 structure (`CD001` at
offset `0x8001`) with no Xbox magic present.

You don't need to convert anything by hand. If you try to launch a raw rip, the launch fails with
an error and a **Convert with extract-xiso** button appears right below it. Click the button and
Peach 1UP converts the image in place, stripping the video partition and rebuilding the XDVDFS
layout, no separate download or command line needed. A progress indicator shows while the
conversion runs (it can take a while for large images).

When conversion finishes, the original rip is kept as `<filename>.old` in the same folder as a
backup. It's safe to delete manually once you've confirmed the converted image launches correctly
— Peach 1UP won't delete it for you. Click **Launch** again to play.

extract-xiso is bundled with Peach 1UP and used under its own open-source license; see
**Settings → Attribution** for details.

### Compressing to CHD

CHD (Compressed Hunks of Data) is a lossless archive format developed by MAME for disc images. It
works for PS1, PS2, and Dreamcast GDI, and compresses 30–50% smaller than a raw image. The process
is fully reversible. Use [chdman](https://docs.libretro.com/guides/chd-guide/) to convert:
`chdman createcd -i input.cue -o output.chd`. For GDI images use `-i input.gdi` instead. DuckStation,
PCSX2, and Flycast all read CHD natively.

### Not supported yet

**Game Boy, Game Boy Color, Game Boy Advance, Genesis/Mega Drive, and 32X are not supported at
all**, Peach 1UP doesn't detect these formats or know how to launch them. There's no partial
support or manual workaround; these platforms simply aren't wired up yet. Don't file bugs for
missing detection or launch on these formats, it's expected for this alpha.

If a platform isn't listed in either table above, assume it isn't supported yet.

### PS1: .bin/.cue vs .iso

A `.bin`/`.cue` pair and a `.iso` are functionally equivalent for most PS1 games. The `.cue` sheet is a
plain-text track index pointing to one or more `.bin` files that contain raw sector data. A `.iso`
contains only the 2048-byte data sectors without error-correction bytes. Games that use CD audio
tracks require `.bin`/`.cue` because `.iso` cannot store audio tracks. CHD supersedes both, it compresses
the full sector data including audio and is the preferred format for long-term storage.
