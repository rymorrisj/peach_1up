# Peach 1UP — Decision Log

| Date       | Decision                                                             | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2026-05-07 | Windows emulator launches run under a dedicated low-privilege user   | Running emulators as the same user as the Peach 1UP backend exposes the owner's home directory and profile data to compromised emulator code. A dedicated local account (`peach_sandbox`) with restricted ACLs limits damage: emulators can only read binaries and media paths explicitly granted to that account, not arbitrary user files. This is a defence-in-depth measure and a stepping stone toward stronger isolation (e.g. AppContainer).       |
| 2026-05-07 | Job Objects required for Windows emulator launches where available   | Job Objects provide reliable process-tree lifecycle management and CPU limits. All Windows emulator launches must be assigned to a Job with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` and a sane default CPU cap. This guarantees that emulator trees are torn down if the backend exits and reduces the risk of thermal or power spikes. When assignment fails due to OS limitations, the launch is logged and treated as a weaker fallback.                  |
| 2026-05-07 | AppContainer and Win32 App Isolation deferred to a later phase (P8+) | AppContainer and emerging Win32 App Isolation features provide a stronger security boundary than a low-privilege user plus Job Objects, but require significant investment: installer-time provisioning, ACL management for container SIDs, and careful GPU/device access handling. They are tracked as a future enhancement after the low-privilege user and Job Object baseline is stable and well-tested on Windows 10/11.                             |
| 2026-05-07 | Windows Firewall COM network blocking removed                        | Firewall rule creation via Windows COM requires elevation, fails with E_ACCESSDENIED on standard installs, and is the wrong isolation primitive for this use case. Removed entirely. Network isolation is now emulator-native — DOSBox-X disables the NE2000 adapter, 86Box omits the network device from machine config, VirtualBox sets --nic1 null via VBoxManage. No elevation required. Controlled by enable_networking profile flag, default false. |
| 2026-05-07 | enable_networking added to profile model, default false              | Users can enable networking per profile for software that requires it. When false the emulator launches with its network adapter disabled or absent. When true the emulator default is used. This gives users explicit control and keeps the default posture safe without requiring host OS firewall changes.                                                                                                                                             |
| 2026-05-07 | Alembic removed in favour of SQLModel create_all()                   | Alembic adds migration overhead that is not justified while no real user data exists and the DB can be wiped freely. SQLModel create_all() on startup is sufficient for this stage. Alembic will be reconsidered when the app reaches alpha and user data must be preserved across schema changes.                                                                                                                                                        |
| 2026-05-07 | SQLAlchemy + Pydantic dual-layer replaced with SQLModel              | The three-layer model (SQLAlchemy ORM + Pydantic schema + TypeScript type) was a hedge toward Postgres migration that is not planned. SQLModel collapses ORM and schema into one definition, reducing duplication and manual synchronisation. Postgres or MariaDB migration remains possible as a future config change.                                                                                                                                   |
| 2026-05-07 | FastAPI OpenAPI spec designated single source of truth for types     | Frontend TypeScript types will be generated from the FastAPI OpenAPI spec via openapi-typescript into /shared/types.ts. Hand-maintained frontend/src/types/index.ts is deleted. Type changes flow from Pydantic/SQLModel model to OpenAPI spec to TypeScript automatically.                                                                                                                                                                               |
| 2026-05-07 | Windows 7 support added to VirtualBox era mapping                    | VirtualBox handles NT-based systems well. Windows 7 added as a supported era alongside XP. 86Box remains the accuracy backend for Win95/98 only.                                                                                                                                                                                                                                                                                                          |
| 2026-05-06 | Win9x FastAPI launch path has OSPlatform signature mismatch          | launch_media() in backend_router.py calls launch_fn(media_path, era, executable_path) for all                                                                                                                                                                                                                                                                                                                                                             |

backends. But box86.launch() and virtualbox.launch() expect an OSPlatform dataclass as their first positional argument — they were designed for the P2 YAML-backed platform model
and never updated when P3.5 introduced the database-backed launch contract. A launch attempt for win95, win98, or winxp through the FastAPI endpoint will raise TypeError at
runtime. Resolution belongs at the start of P5: either update box86 and virtualbox to accept the ORM Profile + media_path + executable_path kwargs, or introduce a platform
resolver in launch_media() that hydrates an OSPlatform from the database before dispatching. |
| 2026-05-06 | Profile model decoupled from media items | Profiles are global reusable launch configurations, not per-media-item records. A media item stores a selected_profile_id (nullable FK). Launch is blocked until a valid profile is selected. Rationale: users share a DOS Default across their whole DOS library and create a DOS+ for specific games needing extra extensions. Tying profiles to items would force duplication of identical config. |
| 2026-05-06 | Pre-seeded platforms and profiles at first run | On first run, backend seeds 8 emulator platform records and 12 era default profiles. Seeding is defensive — skips with logger.warning if migration not applied rather than crashing. Platforms are created even when the binary is not detected; UI shows official download link instead of a launch option. Users never need to manually create a platform record for a supported emulator. |
| 2026-05-06 | Library scan path restricted to configured base directories | Scan endpoint validates directory against allowlist of IMAGES_PATH, PROFILES_PATH, ROM_PATH. Requests outside allowlist rejected with 400 and logged. Previous implementation passed directory param directly to scan_directory() with no validation — a SECURITY.md violation. Media collections must live under a configured base directory or the scan will be blocked. |
| 2026-05-06 | SessionMiddleware added; session secret generated and persisted | SessionMiddleware was missing from main.py causing profile switching to silently do nothing. Secret generated on first run via get_or_generate_session_secret(), persisted to settings.yaml, never logged or returned by any API endpoint per SECURITY.md. |
| 2026-05-06 | Launch flow requires profile selection; Launch button gated | A media item cannot be launched without a selected profile. Launch button is greyed out and non-interactive until a valid profile_id is assigned to the item. Profile dropdown on item detail filters by matching era first, allows cross-era override with a visible warning. This is the enforced launch contract going into P5. |
| 2026-05-06 | Native installer replacing Tauri and Docker | Peach 1UP runs as a Windows service (NSIS/WiX installer) or Linux systemd service (deb/AppImage). PyInstaller compiles the FastAPI backend to a standalone executable. React frontend served as static files by FastAPI. pystray provides tray icon. Browser opens automatically on install. No Rust, no Docker, no separate web server. Hobbyists access via localhost:PORT from any device on the network. Build pipeline via GitHub Actions. |
| 2026-05-06 | Tailwind CSS pinned to v3 | Tailwind v4 introduces breaking syntax changes and shadcn/ui does not support it yet. Do not upgrade until shadcn/ui explicitly supports v4. |
| 2026-05-05 | Linux-first application platform | Application infrastructure runs in Linux containers, works on Windows via Docker Engine + WSL2, keeps a single clean codebase without Windows-specific application code paths. Emulators still run natively on the host OS. |
| 2026-05-05 | Docker Engine (headless) as primary install | Not Docker Desktop. WSL2 provides the Linux kernel on Windows. Primary install is one compose command. start.bat fallback for users who cannot run Docker. |
| 2026-05-05 | React and TypeScript for frontend | Chosen over Vue for ecosystem size, community, and job market. TypeScript required throughout. Vite for build tooling. |
| 2026-05-05 | FastAPI as backend framework | Python REST API service, serves React static files in simple mode, separate container in Docker mode. OpenAPI spec auto-generated, openapi-typescript generates typed client for React. |
| 2026-05-05 | SQLite via SQLAlchemy and Alembic | Sufficient for read-heavy single-library usage. SQLAlchemy abstraction means Postgres is a config change later if needed. Prisma rejected as Node-native and awkward alongside a Python backend. |
| 2026-05-05 | Profile is a hardware-era launch preset | Not a per-game config. Bundled presets ship out of the box (e.g. DOS 486DX2/SoundBlaster 16). Fully user-editable and forkable. Multiple profiles can target the same title with different configurations. |
| 2026-05-05 | Library is the primary entity name | Software, game, tool, application, utility are metadata tags not structural distinctions. Mirrors the preservation-first framing. |
| 2026-05-05 | Peach 1UP is a preservation automation tool | The gap it fills is the path from "I have this old media" to "it is running correctly" with no manual emulator configuration. Scope covers PC era (DOS through XP) and first-generation consoles (PS1, PS2, Xbox OG, NES, N64). |
| 2026-05-05 | PS2 moved from PX to P4 | Personal priority, PCSX2 has strong Linux support, fits the console preservation scope. |
| 2026-05-05 | Docusaurus for documentation | React-based, versioned docs, MDX, search. Consistent with frontend stack. Required given project scope expansion. |
| 2026-05-05 | cgroups and namespaces replace Windows Job Objects as isolation layer | Linux-first architecture makes cgroups the correct primitive. Network blocking via network namespaces or iptables per process. Job Objects retained as the Windows host fallback for direct emulator launches until fully replaced. |
| 2026-05-05 | Job Objects bypassed via launch_direct for DOS launches | Error code 5 on Windows 11 blocks job assignment regardless of breakaway attempts. Firewall rules still apply. Revisit when GUI replaces TUI. |
| 2026-05-03 | Basic platform snapshots moved to P2 | The OSPlatform model introduces significant mutable state in P2. A recovery mechanism must ship alongside the state it protects. Basic create and restore only — compression, auto-snapshots, and management stay in PX. |
| 2026-05-03 | VirtualBox as default for Win95/98 and XP | VirtualBox uses hardware virtualization — guest runs at near-native CPU speed. DOSBox-X is software emulation and too slow for most Win9x software. 86Box is opt-in accuracy mode only. Supersedes "86Box for Win 95/98/XP" (2026-04-15). |
| 2026-05-03 | 86Box as opt-in accuracy mode only | 86Box activated by user toggle or known titles database. Never the default path. Presence of Glide DLLs in an ISO does not mean 86Box is required — many games ship multiple renderers. Community-curated known titles YAML is the authoritative signal, not automated heuristics. |
| 2026-05-03 | DOSBox-X scope limited to DOS and Win3.1 | DOSBox-X is the correct tool for DOS and Windows 3.1. For Win95/98 it is a compatibility fallback only — used when a DOS application runs under a Windows shell, not for native Win32 software. |
| 2026-05-03 | OSPlatform model for Win9x/XP | Per-game OS installs are impractical — storage, install time, and complexity are too high. One shared OS image per era with base+working copy pattern is the correct architecture. Matches how eXoDOS, 86Box power users, and VM tools already work. |
| 2026-05-03 | Pre-installed HDD image as primary media path | Installation wizards are impractical for 90s software — installers are interactive and wildly inconsistent. Pre-installed images eliminate the install step entirely. Original media supported as secondary path where user completes install manually. Full wizard deferred to PX. |
| 2026-05-03 | Console scope set to PS1, N64, NES, Xbox OG | First-generation consoles with strong emulator support and clear adapter-pattern fit. PS2 and Win ME deferred to PX — complex config with high variance. Cartridge imaging guide required in P4 for NES/N64 users with physical media. |
| 2026-05-03 | Docker removed from runtime architecture | Docker is no longer used for emulator execution or isolation. All emulators run natively on Windows host under Job Objects. Docker retained only as a historical note — no active role in the project. Supersedes "Docker over VirtualBox" (2026-04-15) and "Docker retained for orchestration only" (2026-04-15). |
| 2026-05-03 | User supplies all ROMs and BIOS assets | No bundled ROMs, BIOS files, or OS images. No automated fetching of copyrighted media. Project provides guidance and links only. User is responsible for sourcing and owning all assets. Supersedes "ROM pack via git clone" (2026-04-16). |
| 2026-04-16 | P1 scope is DOS direct launch only | Proof of concept first. Console backends and Win95/98/XP direct launch deferred to P2. P1 goal: drop in DOS ISO, pick it, game runs, no emulator interaction required. |
| 2026-04-16 | Conditional ROM warning on era selector | Warning shown on Win 95/98 only when ROM pack is absent from ROM_PATH and accuracy mode is available. Checked at render time. Disappears automatically once pack is present, no restart needed. |
| 2026-04-15 | DOSBox-X for DOS and Win 3.1 | No ROM requirement, works immediately, strong DOS accuracy. Scope confirmed as DOS and Win3.1 only — not the primary Win9x path. |
| 2026-04-15 | No persistence in P0 | Testing phase, simplifies lifecycle, persistence in P1+. |
| 2026-04-15 | Disk images only in P0 | Physical drive passthrough adds complexity, moved to P3. |
| 2026-04-15 | Textual for TUI | Keyboard-driven, Python-native, good docs, GUI deferred to PX. |
| 2026-04-15 | DECISIONS.md as separate file | Keeps CLAUDE.md and CONTEXT.md clean, decisions need their own log. |
| 2026-04-15 | Native Windows + Job Objects for emulators | Windows containers unstable on Home edition. Linux containers have no official emulator binaries. Emulators sandbox game code natively. Job Objects cover host process isolation, resource limits, filesystem restriction. Read-only mounts enforced at P0. |
| 2026-04-15 | Networking disabled via Job Objects | Safety rule — no multiplayer in scope, block at process level not container level. |
